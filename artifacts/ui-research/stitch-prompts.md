## Shared design-system rules (apply to all five prompts, and repeated inside each one so every prompt stands alone)

- **Palette (near-monochrome + one accent, color reserved for state only):** background `#FFFFFF` (light) / `#000000` (dark); surface/card `#18181B` (dark-mode panels) with an alternate near-black `#0F1423` for hero/dark sections; text primary `#111827` (light) / `#FFFFFF` (dark); text secondary `#4B5563` (light) / `#A1A1AA` (dark); border/divider `#E5E7EB` (light) / `#27272A` (dark). The **only** saturated colors in the entire UI: primary accent blue `#3B82F6` (buttons, links, active nav state, focus rings) with `#0A66C2` for hover/pressed states, and three semantic status colors used exclusively on pills/badges — success green `#16A34A`, warning/needs-review amber `#D97706`, error/mismatch red `#DC2626`. No other decorative color anywhere — no gradients, no illustration color, no colored icons outside status pills.
- **Typography:** Inter for all prose, headings, and UI chrome (labels, buttons, nav). Geist Mono (or JetBrains Mono) for every tabular or numeric value — ledger amounts, timestamps, document IDs, confidence scores, percentages, column headers in dense tables. Display/heading scale sits around 64px/500-weight for hero-level headlines, scaling down through standard heading sizes; body text 16px/400-weight; small labels/metadata 12px/600-weight in the mono face.
- **Spacing/radius:** 8px base grid unit, 16px default gap between elements, 24px interior card padding, 80px section padding on marketing/landing rhythm only. Card and control (button/input) corner radius 8px — crisp, buttoned-down, not soft/rounded. Status pills and avatars use full pill radius (9999px).
- **Motion:** moderate only — 150-200ms transitions, standard ease easing, applied to text/color/opacity hover states only. No scale/transform flourishes, no bouncy or springy motion, no page-load animation sequences.
- **Platform:** one responsive web codebase, not a separate mobile design. Mobile breakpoint collapses to a single column: summary/balance-style cards stack full-width, dense tables become stacked row-cards, the left sidebar collapses into a bottom icon bar (four to five icons max), consistent with a modern mobile finance app.
- **Cross-cutting exclusions for the whole product:** no login/signup/auth screens anywhere, no multi-currency UI, no general ledger-management UI (no create/edit account flows, no manual posting entry), no decorative color, no illustration-heavy or "consumer playful" tone — this reads as a serious, dense, finance-ops tool in the register of Mercury/Modern Treasury/Stripe, not Wise's consumer friendliness or Ramp/Brex's bold-brand saturation.

## 1. Landing / marketing page

```
Design a marketing landing page for a fintech product called "Ledger Assistant" — a chat-based AI assistant that answers questions about uploaded tax documents (T4/W-2/1099-style slips) with cited, page-level source references, and can post computed figures directly into a real double-entry ledger after user confirmation. Audience: finance-ops and technical reviewers evaluating a serious fintech tool, not consumers.

VISUAL SYSTEM: Near-monochrome base — page background #FFFFFF in light sections, #0F1423 (near-black, slightly blue-tinted) for the hero section. Text: primary #111827 on light backgrounds, #FFFFFF on the dark hero. Secondary/muted text #4B5563 on light, #A1A1AA on dark. Borders/dividers #E5E7EB. The ONLY saturated color anywhere on the page is one accent blue #3B82F6 (used for the single primary CTA button, link hover states, and one small accent glyph) with #0A66C2 as its hover/pressed shade — no gradients, no secondary brand colors, no decorative illustration color. Typography: Inter throughout — a large, restrained display headline around 64px/weight 500 (editorial, calm, NOT bold/loud startup type), standard Inter body copy at 16px/weight 400 for supporting paragraphs. Any numeric/data snippet shown in the hero mockup (dollar amounts, confidence scores, timestamps) renders in Geist Mono or JetBrains Mono, 12-16px, weight 600 for labels. Spacing: 80px vertical rhythm between sections, 8px base grid. Buttons and cards use 8px corner radius — crisp, not soft or bubbly.

LAYOUT: Top navigation bar only (this is the public marketing shell, not the authenticated app) — logo left, nav links "Product / How it works / Security / Docs", one primary blue CTA button right ("See it in action" — NOT "Sign up" or "Log in", since auth is out of scope). Below the nav: a full-bleed dark hero section (#0F1423 background) with a calm, editorial headline (e.g. "Ask your documents. Get a cited answer. Post it to the ledger.") and one sentence of supporting copy in muted gray. The hero's centerpiece visual — this IS the differentiator, not a generic product screenshot — is a mockup of a single chat exchange: a user question in a solid blue message pill, and an assistant reply below it showing prose plus a small bordered citation card (document name, page number, a confidence percentage in mono type, a small paperclip or document icon) sitting directly under the text. Below the hero, three-to-four quiet feature sections in white background, each pairing a short Inter headline with one supporting sentence, covering: cited answers from real documents, confirm-before-post ledger actions, and double-entry accuracy/audit trail — no icons rendered in saturated color, use simple line icons in the muted gray tone. Footer is minimal: logo, one line of copyright-style text, no sprawling link grid.

RESPONSIVE: Single responsive web page. On mobile width, the top nav collapses to a hamburger menu, the hero headline and chat-exchange mockup stack in a single column (chat mockup full-width below the headline), and feature sections stack vertically at full width with no side-by-side grid.

EXCLUSIONS: No login or signup form anywhere on this page. No dashboard screenshot, no pricing table, no testimonials/logos wall, no multi-currency messaging, no bright/saturated brand color beyond the single blue accent, no bouncy or heavy motion in the mockup — it should read as a static, considered still frame.
```

## 2. Dashboard (home)

```
Design the authenticated home dashboard for "Ledger Assistant," a fintech product where users ask an AI assistant questions about uploaded tax documents and get cited answers, some of which post computed figures into a ledger. This dashboard is the demo's "proof of rigor" screen — it surfaces real ingestion and evaluation numbers instead of burying them in a README, mirroring how a serious ledger product like Modern Treasury frames its own dashboard.

VISUAL SYSTEM: Base background #FFFFFF (light mode). Cards/panels use surface #18181B if rendering a dark-mode variant, otherwise white cards with #E5E7EB 1px borders on the light background. Text: primary #111827, secondary/muted #4B5563. The only saturated colors are: accent blue #3B82F6 for the active sidebar item, primary buttons, and links; and status colors used strictly on badges/pills — success green #16A34A for "indexed" / passing-eval states, warning amber #D97706 for "needs_review" / attention items, error red #DC2626 for failed/mismatched states. Typography: Inter for all headings, labels, and prose (widget titles, task descriptions). Every number — balances, counts, percentages, timestamps — renders in Geist Mono or JetBrains Mono, right-aligned where tabular, with metadata/labels at 12px weight 600 mono. 8px grid, 16px gaps between widgets, 24px card padding, 8px card corner radius.

LAYOUT: Persistent left sidebar (dark #18181B or #0F1423 background) with a small set of top-level sections — Dashboard, Chat, Documents, Ledger — the active item highlighted with the blue accent, plus a small "⌘K" command-palette hint near the top. Main content area is a widget grid, four widgets, following Modern Treasury's dashboard composition: (1) top row of 3-4 compact stat tiles — "Documents indexed" count, "Needs review" count (amber badge if >0), "Confidence drop-rate" percentage in mono, "Golden-set eval score" percentage in mono with a green pill if above threshold; (2) a "Needs Attention" widget below, list-style, showing documents currently in needs_review status with an amber left-border flag on each row, exception-first per the "show what needs attention" pattern — this list should NOT be empty in the mockup, show 2-3 realistic flagged rows (document name, reason, timestamp in mono); (3) a "Recent Activity" widget showing a dense right-aligned table of the last several chat sessions and/or ledger postings created via chat, columns: description, amount (mono, right-aligned), timestamp (mono), status pill; (4) a smaller "Corpus" widget showing total ingested document count and last-ingestion timestamp. Data should never look rounded or vague — show specific realistic numbers (e.g. "142 chunks", "3.2% drop-rate", "17/20 eval pass") not placeholder round numbers.

RESPONSIVE: Sidebar collapses to a bottom icon bar (4-5 icons: Dashboard, Chat, Documents, Ledger) on mobile width. Stat tiles stack to a 2-column then 1-column grid. Widgets stack full-width vertically in this order: stat tiles, Needs Attention, Recent Activity, Corpus.

EXCLUSIONS: No account-creation or ledger-management widgets (no "add account," no manual posting entry). No settings/admin panel. No decorative charts unrelated to real backlog data (no vanity metrics). No color outside the blue accent and the three status colors.
```

## 3. Chat interface with citations (core deliverable)

```
Design the core chat screen for "Ledger Assistant" — a RAG assistant that answers questions about a user's uploaded tax documents (T4/W-2/1099-style) with a citation on every answer (document name, page number, location, confidence), and can propose posting a computed figure to a ledger, which the user must explicitly confirm before it posts. Reference pattern: Stripe's Dashboard Assistant drawer, extended with a visible per-claim citation chip (Stripe itself doesn't show one — this product must).

VISUAL SYSTEM: Background #FFFFFF (light) with the persistent left sidebar in dark #18181B/#0F1423 (same sidebar as the dashboard — Dashboard, Chat [active, blue accent], Documents, Ledger). Chat pane background white, message bubbles and citation cards bordered in #E5E7EB with 8px corner radius. The ONLY saturated colors: accent blue #3B82F6 fills the user's message pill and any primary action button ("Post to ledger"); status colors appear only on the confidence badge inside citation cards — green #16A34A for high confidence, amber #D97706 for medium/flagged confidence, red #DC2626 if a claim's confidence is too low to trust. Typography: Inter for all conversational prose (both user and assistant messages) at 16px/400. Geist Mono or JetBrains Mono, small and muted, for every citation's metadata line (document name, "p. 2", confidence "94%", timestamp) and for any numeric figure quoted in an answer (dollar amounts render in mono even inside a prose sentence). A small recurring sparkle-style glyph in the accent blue marks every assistant-authored message as AI-generated, positioned as a small icon at the start of the assistant's turn — consistent and minimal, not heavy chrome.

LAYOUT: Persistent left sidebar as in the dashboard. Main pane is a dedicated full-height chat surface (not a floating bubble). Empty/first-run state: centered greeting text plus 3 suggested-prompt chips below it (e.g. "What was my total reported income on the 2024 T4?", "Show me the withholding summary", "Which documents still need review?") — chips are bordered, not filled, in the neutral border color, no color fill. Conversation state: user turns render as solid blue (#3B82F6) message pills, right-aligned, white text. Assistant turns render left-aligned as plain Inter prose (no bubble/fill, just text on white) with the sparkle glyph marker, and when the answer references a document, a bordered citation card sits directly beneath the prose text — NOT a separate popup — showing: document name, page number, a short excerpt/location description, and a confidence percentage badge, all in the mono face except the excerpt. For the tool-call-to-ledger flow specifically: when the assistant computes a figure via its rule-engine tool (not inline arithmetic), render a distinct structured result card beneath the prose — bordered, slightly elevated, showing the computed figure in large mono type, the source document/page it was derived from, and a primary blue button labeled "Post to ledger" as a clearly separate, deliberate confirm action (never auto-posted) — this card should look visually distinct from the plain citation card, closer to a receipt/confirmation panel. If retrieval finds nothing relevant, render the assistant's turn as plain prose stating that explicitly (e.g. "I couldn't find that in your documents") with no citation card and no fabricated answer — show this as one of the example turns in the mockup. A persistent text input with send button sits fixed at the bottom of the pane.

RESPONSIVE: On mobile width, the sidebar collapses to a bottom icon bar, the chat pane becomes full-screen, citation and confirm-action cards remain full-width below their message (already single-column by design), suggested-prompt chips wrap to two rows instead of one.

EXCLUSIONS: No floating chat bubble/widget pattern — this is a dedicated full-height pane, not a popup. No answer anywhere in the mockup without either a citation card or an explicit "not found" statement — never show prose asserting a fact with no source. No inline math shown as the assistant "typing out" a calculation — computed figures always come from the distinct tool-result card. No auto-posted ledger entries — the confirm button must be visibly a separate, unclicked action in the mockup.
```

## 4. Document library

```
Design the document library screen for "Ledger Assistant," showing every uploaded tax document and its ingestion/indexing status. Each document has a status of exactly one of: pending, needs_review, or indexed — this is real ingestion-pipeline state (OCR extraction, confidence-filtering, chunking, embedding), not a generic file-manager status.

VISUAL SYSTEM: Background #FFFFFF with the same persistent dark left sidebar (Dashboard, Chat, Documents [active, blue accent], Ledger). Table/card surfaces bordered #E5E7EB, 8px radius. The ONLY saturated colors: accent blue #3B82F6 for the active nav item and any primary button (e.g. "Upload document"); status pills in green #16A34A for "indexed", amber #D97706 for "needs_review", neutral gray (not a saturated color — use the muted text-secondary tone) for "pending" since it's a transitional, not urgent, state. Typography: Inter for document names and any prose/notes column. Geist Mono or JetBrains Mono, right-aligned, for every numeric/technical column — ingested-at timestamp, page count, confidence-drop-rate percentage, source_type code. Column headers use the mono face at 12px/weight 600, uppercase tracking, matching a dense audit-table convention.

LAYOUT: Persistent sidebar as in the other screens. Main content: a page header with title "Documents" and one primary blue "Upload document" button top-right (upload as an ingestion trigger only — no document editing). Below the header, a row of filter chips: "All", "Pending", "Needs review" (amber dot), "Indexed" (green dot) — "Needs review" chip should be visually distinguishable so it reads as the exception-first default view. Main body is a dense sticky-header table, NOT a card grid, with columns: Document name (Inter), Source type (mono, e.g. "tax_slip"), Ingested at (mono timestamp), Status (colored pill), Confidence drop-rate (mono percentage, right-aligned). Rows with needs_review status carry a subtle amber left-border accent on the row itself, reinforcing the exception-first flagging pattern — include at least 2-3 needs_review rows and a mix of pending/indexed rows in the mockup so the state distribution looks real, not empty. No truncated or rounded values anywhere — full document names, exact percentages (e.g. "4.7%" not "~5%"), exact timestamps.

RESPONSIVE: On mobile width, the sidebar collapses to a bottom icon bar and the table collapses into a stacked list of row-cards — one card per document, document name and status pill on the top line, mono metadata (source type, timestamp, drop-rate) on a secondary line below, right-aligned where it was right-aligned in the table.

EXCLUSIONS: No bulk document management (no multi-select delete, no folder/tagging system, no rename). No document preview/editing UI in this screen — status and metadata only. No color on rows beyond the needs_review amber accent and the status pill itself.
```

## 5. Ledger / postings view — read-only, tool-call provenance only

```
Design a strictly READ-ONLY ledger postings screen for "Ledger Assistant." This screen shows ONLY postings that were created by the chat assistant's tool-call flow (a user asked a question, the assistant computed a figure via its rule engine, the user confirmed, it posted) — it is explicitly NOT a general ledger-management interface. There must be no create, edit, or delete affordance anywhere in this screen; every posting traces back to a source document, page, and location, and to the chat session that produced it.

VISUAL SYSTEM: Background #FFFFFF with the same persistent dark left sidebar (Dashboard, Chat, Documents, Ledger [active, blue accent]). A small badge or label near the page title reading "Read-only — created via chat" in muted secondary text, reinforcing scope. Table/card surfaces bordered #E5E7EB, 8px radius. The ONLY saturated colors: accent blue #3B82F6 for the active nav item and any link (e.g. "View source document"); a green #16A34A "Balanced" status pill on every posting (since balance is invariant-enforced, this should always read as balanced/green in this read-only view — no amber/red posting states here, those belong to the document library, not the ledger). Typography: Inter for description text and labels only. Geist Mono or JetBrains Mono for every ledger figure — this is the single most important typographic rule on this screen: posting IDs, debit/credit amounts (right-aligned), timestamps, and source_page/source_location values are ALL in mono type, following Modern Treasury's right-aligned tabular-numeral convention, never in cards with left-aligned casual numbers.

LAYOUT: Persistent sidebar as in the other screens. Page header: title "Postings", the read-only badge described above, and NO action button (deliberately absent — no "New posting" button anywhere). Main body is a dense table, Modern Treasury style: columns Posting ID (mono), Description (Inter), Amount (mono, right-aligned, formatted as currency), Created at (mono timestamp), Source (a small document-name + page chip, e.g. "T4_2024.pdf · p.2", clickable/linked in blue), Status ("Balanced" green pill). Selecting a row opens a detail panel (side panel or modal, styled like Stripe's inline payment-record card) showing: the posting description as a small label, the amount in large mono type as the visual focal point, the "Balanced" green status pill, a breakdown of the debit and credit entries (account name + mono amount for each, confirming they net to zero), a "Source" section listing the originating document name, page, and location alongside a "View in chat" link back to the originating session — no edit controls anywhere in this panel, every field renders as static text. Include 4-5 realistic rows in the mockup, all balanced, with real-looking descriptions (e.g. "Total reported income — T4 2024") rather than placeholder "Posting #1" labels.

RESPONSIVE: Sidebar collapses to a bottom icon bar. The table collapses to stacked read-only row-cards (description + amount on the top line, mono metadata below, source chip and status pill visible). Selecting a row opens the detail panel as a full-screen read-only sheet rather than a side panel.

EXCLUSIONS: No create/edit/delete button or icon anywhere on this screen. No account-management UI (no chart-of-accounts view, no "add account"). No manual posting-entry form. No postings shown that aren't explicitly tagged as chat-originated — this is not a general ledger browser. No color on this screen beyond the blue accent (links/nav) and the green "Balanced" pill — do not introduce amber/red status here, since only tool-call-confirmed, already-balanced postings ever reach this view.
```
